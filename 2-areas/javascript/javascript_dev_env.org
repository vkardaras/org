* Installing Node.js

** Introducing Node.js and npm

- *Node.js:* A JavaScript runtime built on Google's open source V8 engine that can execute programs outside a browser ohn Windows, Mac, and Linux.
- *npm:* Node.js provides a package manager called the Node Package Manager or "npm" to manage third-party code dependencies.

*** How IDEs take advantage of Node.js

- Language tools
- Debugging tools
- Package tools
- Task runners and scripts

*** How different runtimes compare

**** Browser

- Runs on the end-user's machine within their browser.
- Typically needs to be compiled by tools like Webpack or Vite.
- Dependencies are managed by =npm=.
- Client-side (frontend).

**** Node.js

- Runs without a browser using =node= executable.
- Typically does not need to be compiled.
- Dependencies are managed by =npm=.
- Server-side (backend)

#+begin_src shell

*** How npm works

=package.json --npm install--> npm registry --> node_modules --> package-lock.json=

**** ~package.json~: The heart of a javascript project

The =package.json= file contains metadata about the project, including dependencies.

#+begin_src json
  {
      "name": "package-name",
      "version": "1.0.0",
      "dependencies": {
          "express": "5.x"
      },
      "devDependencies": {
          "eslint": "^8.0.0"
      }
  }
#+end_src

- =dependencies= are Runtime dependencies
- =devDependencies= are Development-time only dependencies

*View the versions of a package*

#+begin_src shell
  # view the versions of express package
  npm view express versions
#+end_src

**** ~package-lock.json~: The nervous system of a javascript project

The =package-lock.json= is a lockfile containing exact dependencies being used

** Adding a package dependency

Add a package for accepting commands during execution. e.g. =node index.js add 5 2=

#+begin_src shell
  # example for package yargs
  # install the latest version
  npm install yargs
  # force npm to add a dependency entry
  npm install yargs --save
  # install a specific version
  npm install yargs@latest-13

  # install as development deepndency
  npm install esling --save-dev
#+end_src

*Why separate development dependencies*

- They won't be installed in a productions Node.js environment.
- They help teammates know what packages are not used at runtime.

** Updating a package dependency

#+begin_src shell
  # list outdated dependencies
  npm outdated

  # print what npm will do before executing the update command
  npm update --dry-run

  # update to the latest wanted version
  npm update

  # update to the latest version of a package
  npm install yargs@latest 
#+end_src

#+begin_quote
=npm update= will only update to the highest-supported wanted version, not the latest version
Transitive dependencies are tracked in the =package-lock.json= by =npm=
#+end_quote

*** Challenges of updating packages

- Complex to manage many dependencies
- Newer versions aren't always backwards-compatible
- Security vulnerabilities can be found downstream

Use automation tools for updates like =renovate= (https://www.mend.io/renovate/)

** Troubleshooting npm issues

*** Fixing peer dependency errors

*Peer dependency error*
Some packages require other packages to be at a certain version range, otherwise npm will throw a peer dependency error.

#+begin_example
ERESOLVE unable to resolve dependency tree
#+end_example

*Fixing peer dependency errors*
Ultimately the package maintainers need to update their version range but there are ways to workaround it if you know the packages are compatible.

#+begin_src shell
  npm install <package> --force
  npm install <package> --legacy-peer-deps
#+end_src

*** Random package installation failures

*Error when pulling down a npm package*
HTTP errors can sometimes happen when packages change in the registry over time

#+begin_example
code EPROTO
errno EPROTO
request to https://registry.npmjs.org/package failed,
reason: write EPROTO...
#+end_example

*Reset node modules*
Sometimes your node_modules folder will get into an inconsistent state. The nuclear option is to completely remove the directory.

#+begin_src shell
  rm -rf node_modules
#+end_src

*Clean npm cache*
For even harder issues, you can try cleaning the npm cache on your system (in addition to removing node_modules).

#+begin_src shell
  npm cache clean --force
  npm cache verify
#+end_src
